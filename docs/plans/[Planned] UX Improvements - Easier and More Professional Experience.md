## Context

مراجعة شاملة لتجربة المستخدم (2026-10-01) بناءً على معرفة كاملة بكل صفحات الموقع
وأنظمته بعد جولات الفحص والتنفيذ السابقة. الأساس ممتاز (PWA، إشعارات فورية،
أوفلاين للزيارات، صلاحيات محكمة، تشفير بيانات) — هذه الخطة لا تلمس ما يعمل جيدًا،
بل تسدّ الثغرات الحقيقية التي يعانيها المستخدم اليومي:

1. لا يوجد "نسيت كلمة المرور" رغم وجود جدول `password_reset_tokens` — المستخدم
   الناسي يرى "تواصل مع المسؤول".
2. البحث في الهيدر يبحث في المخدومين فقط.
3. رابط دعوة الأسرة موجود لكن مشاركته تتم يدويًا.
4. صاحب طلب الانضمام المقبول ينتظر 60 ثانية لاكتشاف قبوله بنفسه.
5. الحالات الفارغة نص جامد بلا إجراء.
6. لوحة الخادم بلا صفحة إشعارات (الجرس فقط).
7. لا تفضيلات إشعارات لكل مستخدم.
8. الأوفلاين للزيارات فقط — الميدان بلا إنترنت يرى شاشة فارغة.
9. رفع الملفات الطبية بدون كاميرا/ضغط.
10. الزيارات المجدولة قائمة بلا تقويم.
11. السبينر بدل السكيلتون، التقارير بلا فلاتر الصفحة، الإنجليزية ناقصة في /servant،
    وديون تقنية موثقة.

**قاعدة التنفيذ (كالعادة):** كل مرحلة = كود + اختبارات + بناء + نشر حي + سجل
تقدم في هذه الخطة قبل الانتقال لما بعدها. المرجع الإلزامي: `DEPLOYMENT.md`.

## Phase 1 — سد ثغرات UX الحرجة  ·  جلسة إلى جلستين

**Goal:** إزالة أكبر مصادر الإحباط اليومي للمستخدمين والمسؤولين.

- [ ] **1. استعادة كلمة المرور ذاتيًا** (`ForgotPasswordController` + `ResetPasswordController` + بلدان views):
      روابط `password/reset` و`password/email` محمية بـ throttle، توكن عبر
      Mailtrap، رسائل عربية واضحة، وصفحة الدخول تربط "نسيت كلمة المرور؟".
      شرط مسبق: Mailtrap يعمل على الإنتاج (قرار مالك مطلوب).
- [ ] **2. بحث عام موحّد** (`GlobalSearch` مكون + route `app.search`):
      نتائج مصنّفة (مخدومون/زيارات/خدام/طلبات انضمام) بصفحة نتائج، تحترم
      السياسات نفسها (`WebAppScope`)، والهيدر يوجّه إليها بدل بحث المخدومين فقط.
- [ ] **3. مشاركة رابط الانضمام عبر واتساب** (زر في `service-group-profile-page`):
      يفتح `wa.me` بنص عربي جاهز + رابط `/register/{token}`، مع زر نسخ بديل.
      إعادة توليد التوكن من نفس زر الإدارة الحالي.
- [ ] **4. انتظار → دخول بسلاسة** (`waiting-page`):
      زر "تحديث الحالة الآن" (استدعاء فوري) + عند اكتشاف `is_active=true`
      تحويل تلقائي إلى `homeRoute()` بدل انتظار الدورة القادمة.
- [ ] **5. حالات فارغة ذكية** (`x-web-app.empty-state` توسّع مكوّن):
      يقبل `action-url` + `action-label` — زر مباشر داخل الحالة الفارغة
      (أضف أول مخدوم / سجّل أول زيارة / أنشئ أول زيارة مجدولة) في كل الصفحات
      التي تستخدمه.

**Exit criteria:** سيناريو "نسيان كلمة المرور" يكتمل ذاتيًا من البريد حتى الدخول؛
بحث "أحمد" يجد المخدوم والزيارة والخادم معًا؛ مسؤول يشارك رابط أسرة عبر واتساب
بضغطة؛ متقدم مقبول يدخل لوحته بضغطة واحدة؛ الصفحات الفارغة تقترح الإجراء.

## Phase 2 — تسهيل الاستخدام اليومي  ·  جلسة إلى جلستين

**Goal:** أدوات يومية أقوى للخادم الميداني والمسؤول.

- [ ] **6. صفحة إشعارات كاملة في `/servant`** (مكوّن `Servant\NotificationsPage`
      يعيد استخدام منطق `WebApp\NotificationsPage` مع تخطيط الخادم):
      قائمة + فلترة + تحديد كمقروء + رابط `app.notifications` في قائمة الخادم.
- [ ] **7. تفضيلات الإشعارات** (جدول `notification_preferences`: user_id + type
      + enabled، migration آمنة):
      toggles في الملف الشخصي لأنواع غير حرجة فقط (أعياد ميلاد/تذكيرات مجدولة/
      عدم زيارة/مخدوم جديد)، و`InternalNotificationService` + الأوامر تتحقق
      منها قبل الإنشاء. الحالات الحرجة والإشعارات الإدارية لا تُكتم إطلاقًا.
- [ ] **8. أوفلاين أعمق للخادم** (`offline-cache.js` + IndexedDB):
      تخزين قائمة المخدومين المعيّنين (اسم/كود/حالة حرجة/آخر زيارة) عند كل
      تحميل موصول، عرضها دون شبكة مع شارة "بيانات محفوظة بتاريخ …"، وبيانات
      حساسة (ملاحظات طبية) **لا** تُخزَّن محليًا.
- [ ] **9. رفع الملفات الطبية بالكاميرا + ضغط** (فورم الملف الطبي):
      `input capture="environment"` على الموبايل + ضغط canvas حتى 1600px/80%
      قبل الرفع، مع رسالة حجم واضحة.
- [ ] **10. تقويم الزيارات المجدولة** (تبويب "تقويم" في `ScheduledVisitsPage`):
      شبكة أسبوعية/شهرية بسيطة (CSS خالص بلا مكتبة) تُظهر الزيارات المعلقة
      حسب اليوم، النقر يفتح نفس تفاصيل الزيارة. القائمة تبقى الخيار الافتراضي.

**Exit criteria:** الخادم يرى إشعاراته كاملة من هاتفه؛ مستخدم يكتم أعياد الميلاد
فلا تصله؛ خادم بلا شبكة يرى مخدوميه ببيانات محفوظة؛ صورة طبية تُلتقط بالكاميرا
وتُرفع مضغوطة؛ الزيارات المجدولة تُقرأ من التقويم بلمحة.

## Phase 3 — تلميع احترافي  ·  جلسة

**Goal:** إحساس الجودة والسرعة + تنظيف الديون الموثقة.

- [ ] **11. Skeletons للقوائم** (`x-web-app.list-loading` يتطور): هياكل رمادية
      متحركة مكان الصفوف/البطاقات أثناء التحميل بدل السبينر الوحيد.
- [ ] **12. تصدير بفلاتر الصفحة** (ReportController يقبل نفس معاملات الفلترة):
      زر "Excel/PDF" في رأس قوائم المخدومين والزيارات يصدّر ما يراه المستخدم
      الآن (بحث + فلتر)، مع احترام نفس السياسات.
- [ ] **13. إكمال الإنجليزية في `/servant`**: ترجمة العناوين الثابتة وعناوين
      الصفحات (فحص `resources/lang/en` وسدّ الفجوات).
- [ ] **14. تنظيف الديون التقنية الموثقة**:
  - [ ] حذف `tests/Feature/FcmTokenControllerTest.php` المكرر (النسخة في Feature/Controllers).
  - [ ] إصلاح `BellWidgetMaxNotificationsPropertyTest` المتضارب (8 vs 10).
  - [ ] توصيل `node --test tests/js` (اختبار service worker) بـ CI.
  - [ ] إصلاح شريطي التمرير المزدوجين في RTL لسطح المكتب (ملاحظة 2026-09-25).
  - [ ] إخفاء معالج الزيارات بـ display بدل transform (ملاحظة a11y).

**Exit criteria:** التحميل يُظهر سكيلتون؛ زر التصدير في القائمة يعطي ملفًا
مطابقًا للفلاتر؛ /servant كاملة بالإنجليزية؛ صفر ديون في القائمة أعلاه وCI أخضر.

## ما لن يُلمس (ممتاز كما هو)

نظام الإشعارات الفورية (FCM + dedupe)، الأوفلاين للزيارات وsync الميداني، PWA
بworker v9، طبقة الصلاحيات والسياسات، تشفير البيانات الحساسة، مسار طلبات
الانضمام والمراجعة المنفذ في 2026-10-01، ودخول جوجل/الكود ثنائي العامل.

## Open decisions (بحاجة لقرار المالك)

1. **Mailtrap:** استعادة كلمة المرور تحتاج بريدًا يعمل على الإنتاج — هل تُنفَّذ
   المرحلة 1 كاملة بعد تدوير Mailtrap، أم تُنفَّذ الكود الآن ويُفعَّل الإرسال
   لاحقًا؟
2. **الأوفلاين الأعمق:** هل يكفي عرض المخدومين المعيّنين (اسم/حالة/آخر زيارة)
   دون أي بيانات حساسة، أم تريد scope أوسع؟ (التوصية: الأضيق.)
3. **التقويم:** شبكة أسبوعية فقط، أم أسبوعي + شهري؟ (التوصية: نبدأ أسبوعيًا.)
4. **الترتيب:** هل تُنفَّذ المراحل بالترتيب 1→2→3 كما هي، أم تريد إعادة ترتيب
   عناصر داخلها؟
