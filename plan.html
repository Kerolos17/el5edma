مراحل التنفيذ

اضغط على كل مرحلة لعرض التفاصيل. استخدم مربعات الاختيار لتتبع التقدم.

١
نظام التصميم الأساسي
٣-٤ أيام
  • دمج أنظمة الألوان Both - إنشاء طبقة رموز موحدة (design tokens) تجمع بين Web App و Servant. استبدال app-ink و servant-teal بلوحة دافئة واحدة: محايد دافئ، أساسي (teal هادئ أو أزرق دافئ)، لون إضافي (ذهبي/عنبري)، وألوان دلالية.
  • تحديد استراتيجية الألوان Both - استخدام استراتيجية Restrained كأساس (محايد دافئ + لمسة من اللون الأساسي) مع سماح بلحظات Committed (لوحات تشبع في لوحات المعلومات والتقارير).
  • توحيد مكونات UI Both - جرد جميع المكونات والتأكد من أن لكل منها حالات: default, hover, focus-visible, active, disabled, loading. إنشاء مكتبة مكونات مشتركة.
  • توحيد الخطوط والمقاييس Both - مقياس خط واحد بنسبة ≥١.٢٥ بين الدرجات. Cairo للعربية، Inter/System للعناوين الإنجليزية. توحيد border-radius والظلال والتباعد.
٢
تحسينات الواجهة والتجربة
٣-٤ أيام
  • تخفيف وتدفئة تطبيق الويب Web App - تحويل الخلفية إلى كريمية دافئة بدلاً من الرمادي البارد. تقليل هيمنة اللون الأردوازي (slate). استخدام الرمادي الدافئ للألواح والبطاقات.
  • إعادة تصميم التنقل Both - تجميع عناصر القائمة حسب نموذج المستخدم الذهني (الأشخاص > العمل > البيانات > الإعدادات). استخدام تسميات الأقسام. مراجعة الأزرار السفلية للخدم.
  • إعادة تصميم جداول البيانات Web App - تقليل الضوضاء البصرية: حدود أرق، إيقاع عمودي أكبر. إظهار البطاقات المدمجة على الجوال. إضافة حالات فارغة مع توضيح.
  • تحسين لوحة الخدم Servant - صقل العناصر العضوية (SVG بدلاً من CSS). مراجعة تفاعلات السحب السفلي. تدقيق معالج إنشاء الزيارة. عرض حالة المزامنة للبيانات غير المتصلة.
  • تدقيق النماذج المنبثقة Web App - مراجعة ٧ نماذج منبثقة. هل يمكن تحويل بعضها إلى لوحات منزلقة أو نماذج مضمّنة؟ توحيد مكون النافذة المنبثقة مع متغيرات الحجم.
  • تدقيق الخطوط Both - التأكد من مقياس الخط ≥١٫٢٥. طول السطر ٦٥-٧٥ حرفاً للنصوص. تعديل ارتفاع السطر للنصوص الفاتحة على الخلفيات الداكنة.
٣
إمكانية الوصول (WCAG AAA)
٣-٤ أيام
  • تدقيق التباين Both - فحص جميع ألوان النصوص والعناصر الصغيرة. الحد الأدنى ٧:١ للنصوص العادية، ٤٫٥:١ للنصوص الكبيرة (AAA).
  • حجم أهداف اللمس Both - جميع العناصر التفاعلية ≥٤٨×٤٨ بكسل. التركيز على الجوال: الأزرار السفلية، فلاتر البحث، أزرار الإجراءات.
  • مؤشرات التركيز Both - توحيد نمط :focus-visible (مخطط ٣px + ١px offset). اختبار التنقل بلوحة المفاتيح عبر كل صفحة.
  • دعم قارئ الشاشة Both - إضافة aria-label للأزرار ذات الأيقونات فقط. role='dialog' + aria-labelledby للنوافذ المنبثقة. aria-live='polite' للإشعارات.
  • الحركة المخفضة Both - إكمال دعم prefers-reduced-motion: الهيكل العظمي ← ثابت، انتقالات الصفحات ← فوري، الفقاعات العائمة ← تدرج ثابت.
٤
صفحات رئيسية متعمقة
٥-٧ أيام
  • لوحة المعلومات الرئيسية Both - إعادة تصميم بطاقات الإحصائيات بلوحة دافئة. إضافة جدول زمني للأنشطة الأخيرة. أزرار إجراء سريع للمهام الشائعة.
  • صفحة المستفيد Both - إضافة صورة رمزية، بطاقة اتصال مع هاتف قابل للنسخ، شريط ملخص، جدول زمني للزيارات والصلوات. كشف تدريجي للأقسام.
  • تدفق إنشاء الزيارة Servant - تدقيق عدد الخطوات (هل يمكن تقليلها؟). التحقق من صحة الحقول، الحفظ دون اتصال، التأكيد، اقتراح الخطوة التالية. إضافة مؤشر التقدم.
  • صفحة التقارير Web App - إعادة تصميم واجهة التقارير مع معاينات حية لل PDF. تبويب حسب نوع التقرير. إضافة خيارات التصفية والتصدير.
